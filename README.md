# Roster System (Local-First)

Enterprise-structured roster backend for the staffing model:

- `S/N`
- `TEAM`
- `RANK`
- `ID`
- `NAME`
- `Gender`
- `CERT`
- `Scheme`
- `Shift Pattern` (`4W2O` or `5W1O`)
- `Contractual hours`
- `Forecast hours`

`S/N` is auto-generated by the system if left blank during upload or API create.

## Architecture

- API layer: FastAPI routes + request/response schemas
- Service layer: business logic and domain error handling
- Repository layer: SQLAlchemy data access
- Persistence: SQLite for local testing (`./data/roster.db`)
- Testing: pytest + FastAPI TestClient

## Local Run

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
cp .env.example .env
alembic upgrade head
uvicorn roster_system.main:app --reload --app-dir src
```

For local testing, set API token in browser:

- open app
- in sidebar `API Token`, paste `dev-admin-token` (or planner/viewer token)
- click `Save`

Note: dev tokens are disabled by default in code. They are enabled for local by `.env` with `ROSTER_ALLOW_DEV_TOKENS=true`.

API docs:
- `http://127.0.0.1:8000/docs`

Health check:
- `GET /health`

## Core Endpoints

All `/api/v1/*` endpoints require bearer token authentication:

- `Authorization: Bearer dev-admin-token`
- `Authorization: Bearer dev-planner-token`
- `Authorization: Bearer dev-viewer-token`

Production recommendation:
- disable dev tokens (`ROSTER_ALLOW_DEV_TOKENS=false`)
- issue JWTs from IdP and validate issuer/audience/signature

- `POST /api/v1/employees`
- `GET /api/v1/employees`
- `GET /api/v1/employees/{employee_id}`
- `GET /api/v1/employees/{employee_id}/shift-plan?days=28&start_offset=0`
- `PUT /api/v1/employees/{employee_id}`
- `DELETE /api/v1/employees/{employee_id}`
- `POST /api/v1/employees/upload` (multipart form: `file`; worksheet auto-detected)
- `GET /api/v1/employees/upload-template?sheet_name=SAP%20FEB%20(AM)`
- `GET /api/v1/employees/upload-files/latest`
- `GET /api/v1/employees/upload-files/latest/download`
- `GET /api/v1/employees/upload-files/{upload_file_id}/download`
- `GET /api/v1/roster/calendar?year=2026&month=2`
- `PUT /api/v1/roster/calendar` (save manual roster edits for month)
- `POST /api/v1/deployments`:
  - recurring mode: `site_name`, `mode=RECURRING`, `deployment_days`, `requirements[]`
  - adhoc mode: `site_name`, `mode=ADHOC`, `adhoc_start_at`, `adhoc_end_at`, `requirements[]`
  - each requirement item has `product_type`, `required_headcount`, `reporting_from`, `reporting_to`, `next_shift_from`, `next_shift_to`
- `GET /api/v1/deployments`
- `GET /api/v1/deployments/assignments?deployment_date=2026-04-26`
- `PUT /api/v1/deployments/assignments`:
  - body: `deployment_date`, `assignments[]`
  - each assignment item has `site_id`, `slot_index` (0-24), `employee_id`
- `GET /api/v1/dashboard/coverage?date=2026-04-26`
- `GET /api/v1/dashboard/coverage-calendar?year=2026&month=4`
- `POST /api/v1/trainings`
- `GET /api/v1/trainings`
- `POST /api/v1/users`
- `GET /api/v1/users`
- `PUT /api/v1/users/{user_id}/status`
  - user payload requires `staff_id`, `username`, `display_name`, `role`

## Notes for Production Hardening

The API now enforces startup safety checks when `ROSTER_APP_ENV=production`.
If unsafe settings are detected, startup fails fast.

Minimum production requirements:
- `ROSTER_APP_ENV=production`
- `ROSTER_DATABASE_URL` must not use SQLite
- `ROSTER_ALLOW_DEV_TOKENS=false`
- `ROSTER_JWT_SECRET` must be strong (`>=32` chars) and not default
- `ROSTER_JWT_ISSUER` and `ROSTER_JWT_AUDIENCE` must be set
- `ROSTER_CORS_ALLOWED_ORIGINS` must not include localhost
- `ROSTER_SECURITY_HSTS_ENABLED=true`

Still recommended before enterprise go-live:
- Integrate with enterprise IdP JWKS validation and key rotation policy
- Forward audit events to SIEM/immutable log pipeline
- Use distributed rate limiting (e.g. Redis-based) for multi-instance deployments
- Add import pipeline from Excel with validation and approval workflow
